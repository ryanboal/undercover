# Status

The claims pilot in `docs/PLAN.md` and the agent's harness in `docs/PLAN_HARNESS.md` are built: all six phases of each are done.

## Running it

- `npm run dev` starts the backend on port 8000 and the dashboard on http://localhost:5173.
- `uv run -m backend.seed` rebuilds the database from `data/`, putting every claim back in the queue.
- `uv run -m agent` works the whole queue in one run. `uv run -m agent --cap 5` works at most five claims and leaves the rest waiting. `uv run -m agent CLM-1001` works one claim with the claim agent. Each prints a line per claim, and a run ends with its summary. A cap must be at least 1, and only one agent runs at a time on a machine: it holds local port 8765 while it works. All use the real model through OpenRouter.

## Built

- `backend/`: SQLite database seeded from `data/` (never `data/evals/`), at `undercover.db` or the path in `UNDERCOVER_DB`, created on startup when missing. Read operations: `health`, `list_claims`, `get_claim`, `get_policy`, `get_claim_history`, `list_handlers`, `list_steps`, `get_instructions`, `search_documents` (full-text search over the sections of the policy wording and the claims manual) and `read_section`. Workflow operations: `start_claim`, `record_step`, `record_decision`, `pay_claim`, `sign_off_claim` and `release_claim`, which puts a failed claim back in the queue and leaves it for a handler (`needs_handler`) after its second failure, recording the reason as an `error` step. Runs: `start_run` (with a cap), `get_current_run`, `record_todos` and `finish_run`. A claim moves from waiting to in progress to decided, or to waiting for sign-off when an approval pays over the limit in `company.json`. `pay_claim` refuses such a payout with a 403 until a handler signs off, and signing off pays it. The agent's instructions are in `backend/instructions/`, and `get_instructions` serves the instructions for the queue and for a claim. A test checks that every operation follows the API rules.
- `agent/`: the claim agent. `work_claim(claim_id)` starts the claim and runs a fresh claim agent on it with seven tools named after backend operations: `get_claim`, `get_policy`, `get_claim_history`, `search_documents`, `read_section`, `record_decision` and `pay_claim`. Its instructions (`backend/instructions/claim.md`) end with the contents of the wording and the manual, and it reads the sections it needs; each section read is recorded as a `read` step. Middleware retries provider errors and timeouts (3 times) and backend network errors, and stops an attempt after 25 model calls. Any failure before a decision releases the claim, and an approval within the limit that the agent left unpaid is paid by `work_claim`. It returns a line such as `CLM-1001 approve $420.00, paid`. The default model is `deepseek/deepseek-v4.1-flash` with low reasoning effort, or `MODEL_NAME`.
- `agent/queue.py`: the queue agent. `run_queue(cap)` releases any claim an earlier run left in progress, pays any approval within the limit it left unpaid, starts a run, and gives the queue agent four tools: `list_claims`, `record_todos`, `work_claim` (the claim agent as a subagent, one claim at a time, refusing claims beyond the cap) and `finish_run` (refused while a waiting claim could still be worked in the run). If the queue agent stops without finishing, it is told to carry on, twice, and then the harness finishes the run itself.
- `dashboard/`: the queue (`/`), with counts by state (including Needs a handler), the agent's to-do list for the current run with its summary once finished, and a line per claim. A claim in full (`/claims/:claimId`), with its policy, earlier claims, the decision and payment, the agent's steps as it works (including the sections it read and any failed attempts), and a sign-off form for a held payout. The agent's instructions for running the queue and for working a claim (`/instructions`), read only. The queue and a claim page refresh every two seconds. Styled to `BRAND.md` in light and dark mode.
- `e2e/`: tests of the three pages, the agent's steps appearing on a claim page, a handler signing off a held payout, the to-do list filling in and finishing, a section read, and a claim that fails twice needing a handler. Playwright runs its own backend on port 8001 with `e2e/undercover.db`, and its own dashboard on port 5174, so it can run next to `npm run dev`.

## Last live run

On November 22, 2026, after reseeding, `uv run -m agent --cap 5` with `deepseek/deepseek-v4.1-flash` worked five claims in about a minute and a half, oldest submitted first: CLM-1001 approve $420.00 (paid), CLM-1008 approve $2,240.00 and CLM-1011 approve $1,150.00 (both waiting for sign-off), CLM-1010 decline and CLM-1018 refer (proof of value missing for the jacket). The to-do list filled in and was ticked off on the dashboard, no claim failed, and the other 20 claims stayed waiting. Each claim agent read between seven and nine sections of the wording and the manual, and one (CLM-1010) also searched them. Three of the five reasons ran to four or five sentences rather than two or three. These decisions have not been scored against the handlers' decisions in `data/evals/`.
